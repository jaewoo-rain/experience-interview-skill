# 세션 운영

## 1. 분야 감지

사용자가 말한 단어로 분야를 잡고, `분야별_질문과표현.md`의 해당 절로 넘어간다. **분야를 물어보지 말고 말에서 잡는다.** 확실하지 않으면 두 분야의 질문을 섞어 쓰되, 5단계에 들어가기 전에 한 번만 확인한다.

| 신호 | 분야 |
|---|---|
| LLM, 프롬프트, GPT·Claude·Gemini, RAG, 임베딩, 챗봇, 파인튜닝, 토큰, 환각 | AI·LLM 서비스 |
| Kubernetes, Docker, AWS·GCP·Azure, 배포, CI/CD, 서버 죽음, 모니터링, Terraform | 인프라·클라우드 |
| API, DB, 트랜잭션, 동시성, 마이그레이션, 부하, 캐시, 스프링·FastAPI·Node | 백엔드 |
| 파이프라인, ETL, 크롤링, Airflow, 데이터 수집, 대시보드, 전처리 | 데이터 |
| React·Vue·Flutter, 화면, 렌더링, 반응형, 접근성, 앱 출시, 크래시 | 프론트엔드·앱 |
| ROS, 센서, 제어, 아두이노, 임베디드, 모터, 실기, 시뮬레이션 | 로봇·임베디드 |
| 광고, 전환율, 유입, 인스타·블로그 운영, 캠페인, A/B | 마케팅·그로스 |
| 기획, 요구사항, 우선순위, 일정, 회의, 팀장 역할, 발표 | 기획·PM |
| 동아리, 학회, 공모전, 대회, 창업, 학회장, 교내 활동 | 창업·대회·동아리 |

한 사건이 두 분야에 걸치면 **본인이 손으로 한 쪽**을 고른다. "AI 서비스를 배포했다"에서 본인이 모델을 붙였으면 AI, 배포 환경을 만들었으면 인프라다.

## 2. "쓸 만한 경험이 없어요"라고 할 때

가장 흔한 시작점이다. 여기서 예시를 주면 안 된다(금지규칙 R5). 아래 순서로 내려간다.

1. **책·장 나누기**(문구 9)를 먼저 쓴다. 대부분 여기서 후보가 3~5개 나온다.
2. 그래도 없다고 하면 **범위를 낮춘다.** "잘한 일"이 아니라 **"남들보다 시간을 많이 쓴 일"**을 묻는다. 성과가 아니라 시간은 누구에게나 있다.
3. 그래도 막히면 **네 사분면을 하나씩** 던진다. 수업 과제 / 아르바이트·인턴 / 동아리·모임 / 혼자 만든 것.
4. 여전히 막히면 **불편했던 것**을 묻는다. "최근에 '이거 왜 이렇게 불편하지'라고 생각한 적 있으세요?" — 만든 게 없어도 문제 인식은 기록할 수 있다.
5. 마지막으로 **타인의 시선**을 빌린다(래더링 3인칭). "주변에서 당신한테 뭘 부탁하나요?"

⚠️ 5번까지 왔는데도 사건이 나오지 않으면, **없는 것을 만들지 말고 그렇게 기록한다.** "현재 기록 가능한 사건 없음. 다음 프로젝트 마일스톤에서 다시 진행." 빈 채로 두는 것이 지어낸 것보다 낫다.

## 3. 사용자가 답하기 힘들어할 때의 순서

한 질문에 막히면 아래 순서로 내려간다. **같은 질문을 다시 던지지 않는다**(R6).

1. **기다린다** — 침묵. 다음 질문을 얹지 않는다
2. **범위를 좁힌다** — "전체 말고, 그날 오전에 한 일만요"
3. **각도를 바꾼다** — 부재 가정 → 부정 래더링 → 연령 회귀 → 3인칭
4. **넘어간다** — "이건 나중에 다시 볼게요"라고 말하고 다른 사건으로. 나중에 돌아온다
5. **비운다** — `⚠️ 확인 필요`로 남긴다

## 4. 세션 끝 자가 점검

기록을 저장하기 전에 **스스로 감사한다.** ECIT는 면담 3~4건마다 녹음을 들어 유도 질문 여부를 감사하는데, 그것의 1인용 축소판이다.

- [ ] 내가 **예시를 먼저 준 적**이 있는가 (R5)
- [ ] 내가 **숫자·범위를 먼저 말한 적**이 있는가 (R2)
- [ ] 내가 쓴 질문에 **강도 부사·방향성 형용사**가 있었는가 (R3)
- [ ] 사용자가 말하지 않은 것을 **전제로 깔았는가** (R1)
- [ ] **칭찬·감탄**을 했는가. 했다면 그 대목에서만 했는가 (R4)
- [ ] **가정·상상**을 시켰는가 (R7)
- [ ] 역량 이름을 **내가 먼저 규정**했는가 (R9)
- [ ] 질문 대비 반영 비율이 **1:2**에 가까웠는가
- [ ] 수치마다 **4종 세트와 출처 플래그**가 붙었는가
- [ ] **역할 경계(내 것 아님)** 칸이 비어 있지 않은가
- [ ] "생각해 보니…"로 나온 문장을 **🔁 재확인 필요**로 표시했는가

하나라도 걸리면 **그 항목으로 얻은 내용에 `[오염 가능]`을 붙인다.** 지우지는 않는다. 다음 세션에서 다른 각도로 다시 확인한다.

## 5. 기록을 사용자에게 돌려주기

저장 전에 반드시 읽히고 세 가지를 묻는다 (ECIT 교차확인).

> **이게 맞습니까? 빠진 게 있습니까? 수정이 필요한 게 있습니까?**

사용자가 고친 내용이 **원래 말과 다르면** 둘 다 남긴다. 어느 쪽이 맞는지는 본인이 정한다.

## 6. 민감한 내용 다루기

경험에는 건강, 가족, 퇴사 사유, 갈등 상대의 실명 같은 것이 섞여 들어온다.

- **묻지 않는다.** 채용 맥락에서 건강·종교·가족 항목은 차별 이슈이며, 생애사 면담 원본에서도 이 항목들은 빼고 쓴다
- 사용자가 **먼저 말하면** 듣되, 기록에는 **경험에 필요한 만큼만** 남긴다
- 타인은 **역할로만** 적는다. "○○ 선배"가 아니라 "팀원 1명"
- 회사·팀 소유 정보(내부 수치, 미공개 계획)는 **공개 가능 여부를 확인**한 뒤 기록한다. 확인 전에는 `[공개 가능 여부 미확인]`

## 7. 언제 다시 하는가

- **프로젝트 마일스톤 직후** — 배포, 수상, 제출, 발표. 기억은 2주면 절반이 날아간다(Flanagan: 매일 기록 315건 vs 2주 단위 63건)
- **지원 직전이 아니라 평소에.** 마감 앞에서 하는 인터뷰는 "쓸 만한 답"을 만들려는 압력이 걸린다
- 같은 사건을 **두 번째 볼 때**는 새로 묻지 말고, 기록을 읽히고 빠진 칸만 채운다
